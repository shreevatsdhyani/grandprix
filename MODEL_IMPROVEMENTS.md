# Improving the Mood Model

Changes that make predictions better for both existing and newly uploaded clips,
ordered by payoff per unit of effort.

---

## 1. Feed the classifier the full emotion distributions

Each model branch is currently collapsed into a single 0–100 scalar before the
fusion head sees it. Eleven probabilities become two numbers, and the *direction*
of the emotion is lost — a strongly positive clip and a strongly negative one can
land on the same score.

Pass the raw class probabilities into the feature vector instead of the summary
scores. The head can then learn combinations like "high vocal effort **with**
positive words" that it currently has no way to express.

**Where:** `fusion.feature_vector()`, then refit.

---

## 2. Stabilise the per-driver baselines

The verdict depends heavily on which driver a clip is attributed to, because
every feature is divided by that driver's own standard deviation. Drivers with
tight baselines produce inflated deviations from identical audio.

- **Clamp z-scores** to roughly ±3. Anything beyond that is a broken denominator,
  not a measurement, and it saturates the output to 100%.
- **Floor the standard deviation** against the cohort value, so an unusually
  consistent driver can't manufacture extreme scores.
- **Shrink toward the cohort** gradually as clip count grows, instead of the
  current hard switch at three clips.
- **Use median/MAD** rather than mean/stdev — the baselines are built from
  machine-labelled "calm" clips, so a few misfiled ones distort the reference.

**Where:** `baseline.py`.

---

## 3. Fix the dead speech-rate feature

Word timings aren't arriving from the transcriber, so speaking speed is always
blank and the fitted model has learned to ignore it entirely. One of the three
stated fatigue cues is missing.

Either restore word timestamps, or derive the rate from data already on hand:
word count divided by total detected speech duration from the VAD segments.

**Where:** `stt.py`, `prosody.py`.

---

## 4. Build a small human-labelled evaluation set

The training labels were generated by an earlier rule and the model was trained
to reproduce them, so the reported accuracy measures self-agreement, not
correctness. It can even fall as the model genuinely improves.

Hand-label ~100 clips and hold them out permanently. Without this there is no way
to tell whether any change helped.

---

## 5. Validate by driver, not by clip

Leave-one-out validation leaks: a driver's remaining clips stay in the training
set and also define the baseline the held-out clip is scored against. Group the
folds by driver. Expect the number to drop — that one is the honest figure.

**Where:** `scripts/fit_fusion.py`.

---

## 6. Regularise and calibrate

Current settings produce large coefficients that saturate predictions to 100%
confidence. Increase regularisation and add probability calibration so a stated
confidence reflects real uncertainty.

**Where:** `scripts/fit_fusion.py`.

---

## 7. Version the result cache

Analyses are saved once and only recomputed if the file fails to parse. Any model
improvement therefore leaves every previously analysed clip showing the old
verdict.

Store the model/head version alongside each result and treat a version mismatch
as a cache miss, so existing clips pick up improvements automatically.

**Where:** `data/store.py`.

---

## Suggested order

Do **1** and **2** first, then refit — they address the largest source of wrong
predictions and the largest source of instability, and together they are a small
amount of code. Add **4** before trusting any accuracy number, and **7** so the
gains actually reach clips already in the library.
